# Login UI refresh implementation plan

> Implement inline with the executing-plans workflow; keep this scoped to the login page.

**Goal:** Adapt the CTF login's light, centered form to the coding competition login.
**Architecture:** Keep the standalone Blade view and existing form POST, CSRF token, validation and redirects. Use the installed Tailwind styles and one native password toggle; add no dependencies.
**Reference:** `capture_the_flag-compition-system` at `origin/main`, `resources/views/authentication/login.blade.php` and its public layout.

## Design

- White card on a light neutral page, dark text, black primary action, and the reference's restrained spacing and rounded corners.
- Existing sans-serif stack for the form; a small code mark for the competition identity.
- Keep Home and Register links. Show the active event title, wrapping long titles.
- Keep username-only authentication; retain username on failure and never refill a password.
- One Show/Hide button with an accessible name and pressed state; visible keyboard focus and usable mobile controls.

## Review focus

Long event names, malformed old input, password privacy after validation, keyboard activation without double toggling, and narrow screens without horizontal scrolling. Authentication and registration rules remain owned by the existing controllers.

## Verified outcome

The old view reproduced a broken password toggle and a 500 error on malformed saved username input. The refreshed view passes 19 login checks and the password toggle check; all ten frontend scripts and the production build pass. Native Chrome checks covered desktop, 320px width, a 216-character event title, keyboard activation, invalid credentials, and both role redirects. Review identified an unnecessary HTML username length limit that counted Unicode differently from the server; it was removed before completion.
